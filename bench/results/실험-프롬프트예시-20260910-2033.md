## 조건

| 이름 | 무엇을 바꿨나 |
|---|---|
| base | 정본 그대로 — 출력 예시의 client 가 `가상상사` |
| placeholder | 예시 client 를 `○○상사` 로 (샘플 본문의 「가상」과 겹치지 않게) |
| no_example | 출력 예시 줄을 아예 뺀다 (형식은 json_schema 가 이미 강제한다) |
| warn | placeholder + 「본문에 그대로 적힌 상호를 옮겨 적어라」 한 줄 추가 |

## 판정 — **확증. 정본 프롬프트를 고칠 값이 있다**

거래처 정확도(규칙 통과 후) **73% → 86%**, OCR 경유 **3/8 → 5/8**, **본문에 없는 이름을 지어낸 횟수 2 → 0**.
네 조건이 단조롭게 좋아지고, 기제도 확인됐다 — `base` 에서 지어낸 이름 2개가 **정확히 예시의 `가상상사`** 였다.

두 변경이 각각 값을 낸다:

1. **예시 상호를 `가상상사` → `○○상사`** : 73 → 82%. 우리 샘플 본문에 `가상카드`·`가상주유소`·
   `가상세무회계사무소` 가 도배돼 있어 예시와 겹쳤다. ⚠ 이 이득의 일부는 **우리 샘플 특유의 겹침** 때문이라
   실제 사무소 서류에서는 작을 수 있다. 그래도 예시에 그럴듯한 상호를 두는 것 자체가 위험하다는 것은 남는다.
2. **「본문에 그대로 적힌 상호를 옮겨 적으세요. 본문에 없는 이름을 만들지 마세요.」 한 줄 추가** : 82 → 86%,
   OCR 4/8 → 5/8. 이쪽은 샘플과 무관한 **일반적인 환각 억제 지시**라 실제 서류에도 전이될 것으로 본다.
   (`no_example` 도 82%로 같지만, 예시를 없애면 형식 이탈 위험이 생긴다 — 형식은 json_schema 가 잡지만
   예시가 있으면 값의 결이 안정된다. 그래서 `warn` 을 고른다.)

→ **정본(`engine/labels.py` + `bench/label_one.py`)에 `warn` 조건을 반영한다.**
⚠ 프롬프트가 바뀌면 **이전 정확도 값은 그 프롬프트의 값이다.** 22건 기준선을 새 프롬프트로 다시 잰다.
지금 폰에서 도는 회차는 **옛 프롬프트**로 잰 것이다(폰의 `label_one.py` 사본이 그때 것이다) — 그 회차의
정확도 열은 옛 프롬프트 값으로 읽어야 하고, 속도(건당 초·pp·tg)는 프롬프트 길이가 거의 같아 영향이 미미하다.
